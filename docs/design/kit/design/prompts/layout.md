你是一名资深交互设计师兼前端工程师。请阅读 `PRODUCT.md`（产品需求）、`SLICE.md`（本轮范围和要出多方案的区域），以及 `CONCEPT-MODEL.md`（如果有），做一个**布局探索原型**，放在 `app/`。

## 这一步只解决布局和交互，不解决视觉风格
- 技术栈：如果 `SLICE.md` 没指定，用 Vite + React + TypeScript；不使用 UI 组件库或 CSS 框架
- 样式保持**中性、克制**：系统字体、灰阶、8px 间距网格、简单的线性图标。不追求好看，也不要模仿任何品牌产品的视觉风格。之后会有专门的一步统一视觉风格
- 每个视图按 PRODUCT.md 写明的**形态**来做（文档页 / 编辑器 / 列表……）
- 示例数据要有真实感：长标题、空值、很多条、多层嵌套、各种状态都要出现

## 按区域给出多种布局方案
`SLICE.md` 列出的每个区域，做 **2～3 种结构上真正不同的方案**（不是同一结构换颜色或间距）：
- **方案 1 是 SLICE.md 推荐的方向**，作为默认
- 每个方案有一个简短的名字，一句话说明**取舍**（适合什么、牺牲了什么）
- 标出**谁在用这种做法**（真实存在的成熟产品，如 VS Code、Notion、GitHub、Linear）和**实现难度**（常规 / 需要额外工作 / 有技术风险）
- 能用常见交互模式的名称就用（master-detail、inline thread、popover、split view…）
- PRODUCT.md 里标【待定】的功能，只做一个最简单的占位方案，标"暂定"

## 方案切换器
- 页面上有一个可折叠的**方案切换面板**（快捷键或角落按钮打开），每个区域一组单选，切换后立即生效
- 当前选择保存在 URL 里，刷新不丢
- 面板里有「导出选择」按钮，复制一段文字：`A=方案名 B=方案名 …`
- 各区域方案可以自由组合，任何组合下页面都不能坏

## 交互要能真的用
PRODUCT.md「核心流程」里的每个流程都要能点通。需要后端的地方用预先写好的假数据。
