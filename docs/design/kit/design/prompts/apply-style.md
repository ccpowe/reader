`app/` 是一个只做了布局和交互的原型（样式是中性灰的占位），产品需求见 `PRODUCT.md`。

## 任务：给原型套上视觉风格
1. **固定布局组合**：如果原型有方案切换器，按 `PRODUCT.md` 里记录的布局选择设为默认，删除切换器和其余方案的代码
2. **套用风格包**：
   - 通用风格包在 `style/`：`DESIGN.md`（判断规则，先读）、`tokens.css`（变量）、组件 CSS（通用组件类）、`components.html`（样板页，在浏览器里打开就能看到所有类和状态）、`checks/lint.mjs`（检查脚本）
   - 本产品专属的组件在 `project/`：`DESIGN.project.md`、`project-tokens.css`、`project.css`、`components.html`（第一次可能是空的或不存在）
   - **外观以 CSS 类为准**：组件直接使用风格包的类，不要自己重写这些组件的样式。应用自己的 CSS 只负责布局（位置、尺寸、排列）
   - 现有的类不够时：先组合现有的类；还不够，在 `project/project.css` 新建类（用风格包的类名前缀），只用 token，并在 `project/DESIGN.project.md` 写一行"为什么现有类不够"，在 `project/components.html` 加示例
   - 字体、图标按 `style/DESIGN.md` 执行
3. **不要改变**布局结构、视图形态和交互行为。DESIGN 里标 `[模式]` 的规则如果和原型冲突，**以原型为准**，并记进冲突清单
4. **完成前运行** `node style/checks/lint.mjs app`，修到 0（确实无法避免的，写明理由）

## 完成后
1. 运行项目，确认无报错
2. 1440×900 下给每个主要视图和关键交互截图，存 `screenshots/`
3. 写 `REPORT.md`：
   - **冲突清单**：`[模式]` 规则 / 原型现状 / 你的处理
   - 按视觉层规则改了原型外观、可能需要用户确认的地方
   - **风格包里不清楚、只能自己决定的地方**，分三类：① 规则自相矛盾 ② 整块缺失（缺哪个组件）③ 细节数值缺失。每条写你最后怎么处理的
   - 新建了哪些类，为什么现有的不够
   - lint 最终结果；怎么启动
4. 关掉你启动的服务
