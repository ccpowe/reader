# AI 前端设计流程包

把这个目录交给一个 agent（Claude Code、Codex……），它就能带着你把软件的界面设计出来。你不需要懂设计术语：你只需要回答问题、审阅草稿、在几个渲染好的方案里挑。

## 两个流程

| 流程 | 什么时候用 | 产出 | 入口 |
|---|---|---|---|
| **一、风格拆解** | 看中了某个成熟产品的样子，风格库里还没有 | **基础风格包**：忠实复刻原版，检验标准是"有没有原版的味道"，不加个人喜好 | `style/START.md` |
| **二、设计** | 要设计一个新软件（或者给已有软件做界面） | 产品文档 + 可运行的界面原型；你对风格的修改形成一个**风格分支**，可以存回风格库 | `design/START.md` |

### 风格库：基础 + 分支
```
styles/
├── notion/                    # 基础：忠实复刻 Notion
│   └── branches/
│       └── quietpaper/        # 分支：在 Notion 基础上，按某个用户的喜好改过（更克制、图标全灰……）
└── <别的基础>/ ...
```
- 设计新软件时，可以选基础风格原样用，也可以选一个现成分支
- 设计过程中你对风格的修改（校准、换图标……），会形成这个项目的分支；结束时可以存回风格库，下次做同风格的软件直接选

## 怎么开始
在一个新的 agent 会话里说：

> 请阅读 `kit/design/START.md`，按这个流程带我设计一个软件。我的想法是：……

或者：

> 请阅读 `kit/style/START.md`，按这个流程拆解 <某个产品> 的风格。

agent 会自己读需要的文件，每到一个需要你做决定的地方停下来问你。

## 你会被问到的三类事
1. **审阅草稿、回答选择题**（产品做什么）：打勾、划掉、改写，比从零描述容易
2. **给渲染好的方案排名**（长什么样）：每次 4～6 个方案，标前三名和最不喜欢的一个，写一句感受就行
3. **看成品，说哪里不对**：随便说，agent 负责判断这条意见该改哪个文件

## 目录
两个流程各自独立，可以单独拿走：
```
kit/
├── style/                 # 流程一：风格拆解
│   ├── START.md           #   给 agent 的操作手册（8 步）
│   ├── prompts/           #   交给子 agent 的说明：采集、拆解、探针、打包、查矛盾、重建
│   ├── templates/         #   风格决策记录、校准页、探针任务
│   └── tools/             #   注入网页的样式采集脚本
└── design/                # 流程二：设计
    ├── START.md           #   给 agent 的操作手册（9 步）
    ├── prompts/           #   交给子 agent 的说明：布局、套风格、改需求、精修、重建、查矛盾
    └── templates/         #   产品文档、决策记录、概念模型、校准页
```

## 状态
- 流程二的第 1～6 步和第 9 步在真实项目里验证过；第 7、8 步（逐页精修、状态与动效）还没验证，手册里标了 `[未验证]`
- 流程一在一个参考产品（Notion）上走通过一次，8 步都是当时实际做过的
- 遇到手册没写到、或者走不通的地方，agent 应该停下来告诉你，并记进项目的 `reports/流程问题.md`。这些记录是改进这个流程包的依据
