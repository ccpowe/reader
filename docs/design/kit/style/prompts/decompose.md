你是一名资深 Product Designer 和 Design Engineer。本目录有一个参考产品的**产品界面**资料（不是营销页）：
- `capture/`：浏览器自动化采集的原始数据。先读 `manifest.md`；`extract.json`、`components.json`、`focus.json` 是 `getComputedStyle` 的真实值，`animations` 是实际记录到的动画参数
- `screenshots/`（如果有）：额外截图
- `TARGET.md`：参考产品是谁，以及这个风格以后可能用在哪类软件上（决定了要覆盖哪些组件）

任务：**忠实地**逆向还原它的设计决策，目标是让别人只看你的产出，就能做出**有原版味道**的界面。这一步不加任何个人喜好，不「改进」原版。

产出三个文件：`analysis.md`（拆解记录）、`DESIGN-draft.md`（风格规范草稿）、`tokens.css`（全部数值）。下一步会有人**只凭你的规范**，用这个风格去做几个别的小软件（笔记、番茄钟、音乐播放器……），看能不能做出原版的感觉。**不要写任何页面代码。**

先完整看完所有文件。数值优先用 capture 里的测量值，截图用来理解这些数值用在哪里。capture 的统计包含页面上的所有元素，有些值只出现在内容区或第三方嵌入里，不一定属于设计系统：结合出现次数和截图判断。

## 第一步：拆解 → `analysis.md`
按六层逐层写，每层先「观察」，再「解释（为什么这样设计）」，最后「可复用规则」：
1. 信息架构：主要任务、常驻 vs 隐藏的信息、导航模型
2. 视觉层级：第一眼看哪里，靠大小 / 对比 / 位置 / 留白 / 分组中的哪些
3. 视觉系统：字号与字重级数、间距尺度、圆角、颜色角色、边框与阴影、图标风格、信息密度
4. 交互模型：关键操作的状态转换、反馈方式、可撤销与可中断
5. 动效：每个动效的触发 / 起止状态 / 属性 / 时长 / 缓动 / 中断（优先用 capture 的记录；manifest 标「未捕获」的再估计）
6. 细节与一致性：对齐、状态完整性、边界情况

要求：
- 每个数值标 `[测量]`（来自 capture）或 `[估计]`（看图推测）
- 品牌资产（logo、插画、吉祥物、自有图标集、品牌名）单独列出，复刻时用中性的替代品；**除此之外的视觉特征都要保留**，包括你觉得不好看的
- 规则分两层：关于布局、视图形态、区块组成、交互行为的，标 `[模式]`（只是默认值，具体产品可以改）；其余是视觉层
- 禁止事项只写原版**自己不会做**的事（从原版的一致性里归纳出来），不写个人好恶
- 对照 TARGET.md：需要覆盖、但参考产品里没采到的东西（某种组件、状态、深色模式……），列进末尾「缺口」一节
- 看不出来的写"无法判断"，不要编造

## 第二步：写风格规范草稿和 token
- `tokens.css`：用 CSS 自定义属性定义全部数值（颜色角色、字体级别、间距、圆角、阴影、控件尺寸、时长、缓动）。按**角色**命名（`--color-text-secondary`，不是 `--gray-500`）。每个值的注释带来源标签 `[测量]` / `[估计]` / `[推导]`（为满足对比度等约束计算得到）
- `DESIGN-draft.md`：给前端工程师看的风格规范。写**可观察的决策**，不写形容词（✗"简洁现代" ✓"页面只用 1 个强调色，只用于主操作和选中态"）。引用 token 名，不重复写数值。包括：设计意图（3～5 条可检验的）、颜色 / 文字 / 间距的用法规则、每个组件的外观和状态、图标和字体、动效、禁止事项、`[模式]` 默认值、已知不足

写完自查：一个**从没见过这个参考产品**的前端工程师，只看 DESIGN-draft.md + tokens.css，能不能做出风格一致的界面？仍然模糊的地方列进「已知不足」。

## 如果这是一次修订
如果目录里有 `reports/`（上一轮用规范做的小软件的 `REPORT.md`、用户的意见 `FEEDBACK.md`），说明上一版规范做出来的东西不够像原版。**整份重写**三个文件（不要在旧文件上打补丁），逐条处理：用户说不像的地方，回到 capture 里找原版的真实值；数值不对改 token，规则没写清改规范，capture 里本来就没有的写进「缺口」。在 `analysis.md` 末尾加一节「本次修订」，列出每条差异怎么处理的。
