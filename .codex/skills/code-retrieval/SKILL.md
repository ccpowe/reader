# 代码检索

在当前工作区内，根据缺少的证据选择工具，取得足够信息后继续任务。工作区外部的资料不使用这套检索流程；不要切换索引来源或 Serena 路由去查询其他工作区。

## 选择工具

| 当前需要 | 使用工具 |
| --- | --- |
| 实现入口未知，或寻找行为、概念、设计问题的相关代码和文档 | `zvec_grep_search` |
| 根据符号名称查定义、签名或正文 | Serena `find_symbol` |
| 确认某个具体使用处指向哪个声明 | Serena `find_declaration` |
| 查找指定定义的引用方 | Serena `find_referencing_symbols` |
| 了解指定文件有哪些符号及其结构 | Serena `get_symbols_overview` |
| 查精确字符串、配置项、错误信息、正则或文本出现位置 | 原生 `rg` |
| 按名称或路径发现文件 | `rg --files` 配合路径筛选 |

按问题所需的证据判断，不只看是否已知名称或是否跨文件。例如，查 `refreshSession` 的定义用 Serena；找它的设计说明可用 zvec-grep；穷举同名文本用 rg。

`zvec_grep_rg` 可用于需要文本命中的所属符号信息，或只能经 MCP 访问文件的场景。它的 AST 增强只补充语法结构；完整参数、文件列表和输出模式仍使用原生 rg。

## 路径与调用

- 首次使用 Serena 时，通过 `get_current_config` 核对路由是否为当前工作区的绝对路径；不正确时用 `activate_project` 修正为当前工作区。路由只影响当前会话，不必每次查询重复激活。按环境约定读取 `initial_instructions`，避免重复获取已提供的说明。
- Serena 的文件路径相对于当前工作区；zvec-grep 的 `root` 使用当前工作区的绝对路径。
- zvec-grep 查询描述行为和意图，已知名称作为补充线索；用 `globs`、`fileTypes` 限制已知范围。`fts` 是额外检索路线，不是结果必须满足的硬条件。从少量候选开始，有具体缺口再扩大范围。
- `find_symbol` 的名称路径可以是 `method`、后缀 `Class/method`，或文件内完整路径 `/Class/method`；重载索引用从零开始的 `[i]`。知道文件或目录时限定 `relative_path`；需要实现时可直接请求正文。
- `find_declaration` 用文件路径和带一个捕获组的正则定位使用处，捕获目标标识符，并保留足够上下文避免同名歧义。

## 搭配与结果判断

- 根据发现的具体缺口继续：zvec-grep 找到候选后，可用 Serena 解析符号，或用 rg 核对文本；已有明确位置时直接进入需要的工具。无需固定执行全部工具，也不必在读取目标符号前例行查看文件概览。
- zvec-grep 的相关性排名和片段共同出现不能证明调用关系；没有命中也不能证明不存在。Serena 的引用结果依赖语言服务器，引用不全是调用，动态或反射使用可能无法解析。
- 已有片段足够回答问题时，直接使用。修改代码前核对当前工作区的相关代码；索引可能尚未同步本地修改。已经读取或解析过相关当前代码时，不重复读取。
- 证据足够就停止检索。工具不可用、语言不支持或结果不足时，换用适合问题的可用工具，并保留尚未解决的证据缺口；不要重复相似查询来机械确认。

## 索引维护与诊断

- 默认检索使用 zvec-grep 的 `agent` 工具集；创建、更新、克隆、重建和删除索引用 CLI 或管理工具。按已有任务授权执行，不因搜索失败或缺索引自动创建、重建或删除持久索引。
- 从搜索响应读取新鲜度和后台刷新信息，不在每次搜索前查询状态。缺索引、更新失败、明确进度需求时使用 `zvec_grep_index_status`；服务诊断使用 `zvec_grep_server_status`。
- 克隆属于索引准备操作，仅在用户已指定来源并要求初始化当前工作区时执行，不自行选择外部索引。克隆操作不调用模型，但后续检索或更新可能使用远程 Embedding 并触发自动刷新；关闭单次查询刷新不等于关闭 watcher。
