# 开发总工作流

把本 Skill 作为唯一流程编排层。不要把各阶段当成必须依次运行的独立 Skills，也不要让外部 Skill、工具或 Subagent 自行改变项目权威。

## 先判断这次改变什么

根据当前请求会改变的决定加载最少的 reference：

| 当前工作 | 必须读取 |
|---|---|
| 从零散想法建立项目简报、素材和工作区 | [references/init.md](references/init.md) |
| 新增、删除或重新定义功能、流程、页面职责 | [references/product.md](references/product.md) |
| 探索或修改静态 UI、布局、美术风格和视觉素材 | [references/ui-design.md](references/ui-design.md) |
| 选择技术栈、建立代码环境，或修改架构、数据、后端、部署与协议 | [references/architecture.md](references/architecture.md) |
| 编写代码、实现页面、交互、动画或后端行为 | [references/implementation.md](references/implementation.md) |
| 审查、加固、优化或准备交付 | [references/quality.md](references/quality.md) |

创建或更新长期产物、分派 Subagent，或者判断变更影响时，同时读取 [references/project-contracts.md](references/project-contracts.md)。

一个请求可以需要多个阶段。先解决会约束其他决定的上游问题，但只重新打开真正受影响的部分。

## 使用权威而不是记忆传递上下文

- 使用 `PROJECT_BRIEF.md` 保存初始化阶段整理后的原始想法、素材和未决问题。
- 使用 `PRODUCT.md` 保存获批产品功能、主要流程和页面或其他界面职责。
- 使用 Penpot 获批静态页面，用 `DESIGN.md` 保存跨页面复用的视觉语言。
- 使用 `ARCHITECTURE.md` 保存系统设计，使用机器可读接口定义保存前后端协议。
- 使用代码、测试和真实运行结果证明当前实现。
- 使用 `AGENTS.md` 说明 Agent 如何在实际仓库中工作以及何时读取上述文档。
- 使用 `PROJECT_STATE.md` 只索引批准状态、需要复查的产物和开放问题，不复制正文。

用户决定目标、主观设计批准和重要取舍。Agent 可以处理用户明确委托的判断，但必须记录依据和授权范围。

## 运行一个阶段

1. 读取当前请求对应的阶段 reference 和其列出的权威输入。
2. 区分已批准事实、当前实现、候选想法和未知项。
3. 只询问会阻塞当前决定且无法安全推导的问题。
4. 在授权范围内完成工作，并让用户确认该阶段规定的主观或高成本决定。
5. 更新负责该事实的权威产物，不在代码或其他文档中建立隐性第二版本。
6. 执行影响检查，把受影响的产物标记为 `needs-review`。
7. 满足退出门槛后停止本阶段，由本文件重新判断当前请求还需要什么。

## 非线性回流

- 产品功能变化时，检查页面、UI、架构、接口和测试是否仍成立。
- 静态布局、风格或视觉素材变化时，先更新 Penpot 并获得批准，再修改前端代码。
- 交互、动画、运行状态和响应式实现主要在真实代码中验证；若暴露静态设计问题，再回到 Penpot。
- 架构或接口变化时，同步检查前端、后端、产品约束和测试。
- 实现发现契约不可行时，返回拥有该决定的阶段；不要只在代码中偷偷改变产品、设计或架构。
- 用户随时可以提出新想法。把它路由到负责该决定的阶段，不要求从初始化重新开始。

产品功能稳定后，UI 设计与技术基础、架构设计可以并行推进。它们互相提供页面状态、数据和技术约束，并在实现前解决直接冲突。

## 使用 Subagent

让主 Agent 保留用户沟通、路由、冲突整合和权威文档的最终责任。只把可独立验证且边界清晰的工作交给 Subagent，例如官方资料调研、独立视觉方向、明确目录的实现或只读审查。

给每个 Subagent 明确输入、文件或对象所有权、期望输出、禁止事项和验证方式。不要让多个 Agent 同时修改同一权威文档、同一 Penpot Frame 或同一代码区域。主 Agent 接收结果后再统一更新项目权威。

## 使用外部能力

把 Imagegen、Penpot、浏览器以及经过验证的外部方法当成执行引擎。只在对应阶段调用它们，并由本 Skill 决定输入、审批和产物。

吸收新方法时，先用真实任务测试其效果和失败模式，再把有效规则改写到对应 reference。不要直接增加另一个并行的流程控制 Skill。
