# 代码实现

## 何时读取

在编写或修改前端、后端、页面、交互、动画、数据流和测试时读取。

## 必须读取

- `PROJECT_STATE.md`；
- 与当前功能有关的 `PRODUCT.md`；
- 前端工作对应的 Penpot Frame、`DESIGN.md` 和页面设计文档；
- 后端或集成工作对应的 `ARCHITECTURE.md` 与接口定义；
- 适用于目标目录的 `AGENTS.md`；
- 当前代码、测试和运行结果。

只加载当前切片真正需要的文档，不把整个项目历史塞给每个实现 Agent。

## 本阶段负责决定

- 如何在获批产品、UI、架构和接口契约内组织实际代码；
- 交互、动画、响应式行为和运行状态的具体实现；
- 测试策略、错误处理和低成本局部实现取舍。

本阶段不能静默改变产品范围、静态设计方向、系统边界或公共接口。

## 工作方式

### 1. 使用垂直切片

优先按一条可工作的用户过程拆分：页面或入口、必要接口、后端行为、数据和测试一起达到可验证状态。不要默认先写完全部前端再写全部后端。

每个切片开始前列出使用的权威、验收行为和不在本切片中的内容。发现契约冲突时先返回负责阶段，而不是在实现中猜测。

### 2. 分派实现 Subagent

按明确目录、组件、服务或切片分配所有权。给 Subagent 提供相关文档路径、接口、验证命令和禁止修改范围；提醒它不要覆盖其他 Agent 的改动。

不要让多个 Agent 同时修改同一接口定义、共享核心文件或 Penpot Frame。主 Agent 负责合并、跨端集成和向用户说明结果。

### 3. 实现前端和动态体验

以获批 Penpot Frame 作为静态构图和视觉基准，在真实应用中实现响应式、加载、空、错误、权限、溢出和数据变化。

动画、手势、过渡和微交互在真实代码与真实页面中调整，用浏览器或目标设备向用户展示并确认。若修改会改变静态布局、视觉语言或主要素材，先返回 Penpot 更新并批准。

每个页面获得用户确认且真实验证通过后，从最终结果提炼可复用的页面说明或提示词，保存到对应页面设计文档。它描述已完成结果，不替代 Penpot、代码或 `DESIGN.md`；以后可以抽成独立工具 Skill。

### 4. 实现后端和集成

遵守架构与机器可读接口契约，实现鉴权、校验、错误、事务、并发和可观测性中与当前切片有关的部分。使用契约测试或集成测试证明前后端没有各自实现不同协议。

### 5. 持续验证

每个切片执行适用的格式化、静态检查、类型检查、单元、集成、浏览器或设备验证。使用真实应用路由和代表性状态，不把孤立测试页面作为唯一验收证据。

## 用户确认点

- 真实页面中的交互、动画和主观体验；
- 实现发现的产品、设计或架构取舍；
- 会扩大范围、引入新依赖或改变公共行为的方案。

## 持久产物与退出门槛

产出可工作的代码、测试和必要页面复用说明。更新因真实目录、命令或边界变化而失效的 `AGENTS.md`、项目地图和 `PROJECT_STATE.md`。

当当前切片满足产品行为、静态 UI、接口和测试契约，真实集成可运行，用户已确认需要主观判断的动态体验时停止。

## 影响检查

- 实现需要新功能或行为：返回产品阶段；
- 实现需要静态 UI 改向：返回 UI 阶段；
- 实现需要公共接口或系统边界变化：返回架构阶段；
- 代码揭示文档过时：更新负责该事实的文档并复查依赖，而不是仅修改 `PROJECT_STATE.md`。
