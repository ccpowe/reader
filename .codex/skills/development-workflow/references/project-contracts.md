## 权威归属

| 产物 | 负责回答 | 不负责回答 |
|---|---|---|
| `PROJECT_BRIEF.md` | 用户最初表达了什么、提供了哪些素材、初始化时怎样理解、哪些仍未决定 | 最终产品、获批设计或完整架构 |
| `PRODUCT.md` | 产品做什么、主要流程、功能、页面或其他操作面职责 | 视觉配方和技术实现 |
| Penpot | 用户批准的静态页面、布局和构图 | 真实动画、运行状态和代码行为 |
| `DESIGN.md` | 跨页面复用的获批视觉语言、令牌和规则 | 单页全部结构、技术栈和业务逻辑 |
| 页面设计文档 | 单页对应 Penpot 对象、静态结构、状态、动态交接和最终复用说明 | 全局产品或设计系统 |
| `ARCHITECTURE.md` | 系统边界、组件、数据、部署、安全边界和重大技术决定 | 产品价值与静态视觉 |
| 机器可读接口定义 | 前后端可实现的请求、响应、事件和兼容协议 | 不能由 schema 表达的产品理由 |
| 代码与测试 | 当前真实实现和可重复行为 | 用户未来希望产品变成什么 |
| `AGENTS.md` | Agent 在对应目录如何工作、运行什么以及读取哪些权威 | 产品、设计和架构正文 |
| `PROJECT_STATE.md` | 当前焦点、批准状态、需复查产物和开放问题 | 任何上述产物的正文副本 |

同一事实只保留一个主要权威。其他文件链接它，不复制出容易漂移的第二版本。

## 状态与变更

对需要用户或跨阶段确认的产物使用以下状态：

- `draft`：仍在形成，不能约束下游最终实现；
- `approved`：用户已确认，或用户明确授权 Agent 决定并已记录依据；
- `needs-review`：上游事实变化，原批准结果可能失效；
- `superseded`：已有明确替代产物，不再作为当前依据。

处理任何变更：

1. 判断哪个权威拥有被改变的事实；
2. 在该权威中讨论并更新，不先改下游产物；
3. 使用影响矩阵找出可能失效的依赖；
4. 在 `PROJECT_STATE.md` 中将它们标记为 `needs-review`；
5. 只重新讨论受影响部分；
6. 验证并重新批准后恢复为 `approved`。

`PROJECT_STATE.md` 不能替代源文档更新。

## `PROJECT_STATE.md`

保持短小，推荐结构：

```markdown
# Project State

## 当前焦点
- ...

## 权威产物
| 产物 | 路径或对象 | 状态 | 最近决定 |
|---|---|---|---|

## 需要复查
- [artifact] — [triggering change]

## 开放决定
- [问题] — 决定者：[用户/阶段]，阻塞：[工作或无]
```

只在状态、权威位置或阻塞发生变化时更新。不要建立流水账或复制每次对话。

## 影响矩阵

| 改变的权威 | 至少检查 |
|---|---|
| `PROJECT_BRIEF.md` 中的平台或硬约束 | 产品、UI、技术基础、架构、环境、`AGENTS.md` |
| `PRODUCT.md` 中的功能、流程或操作面 | UI、技术基础、架构、接口、实现、测试 |
| Penpot、`DESIGN.md` 或页面静态契约 | 前端实现、素材、可访问性验证 |
| `ARCHITECTURE.md` | 接口、前端、后端、部署、测试、`AGENTS.md` |
| 接口定义 | 前端、后端、契约与集成测试 |
| 运行时实现行为 | 产品、设计或架构文档是否被实现偷偷改变 |
| 技术栈或目录结构 | 环境、架构、所有适用 `AGENTS.md`、命令和 CI |

矩阵用于提出复查候选，不代表每次都必须修改所有项目。记录不受影响的理由即可关闭候选。

## Subagent 契约

主 Agent 负责用户沟通、阶段路由、冲突整合和权威产物的最终写入。分派前明确：

- 单一任务目标和成功条件；
- 必须读取的最小文档与原始证据；
- 明确的文件、目录、Penpot Frame 或只读责任；
- 允许和禁止的修改；
- 结构化输出与验证命令；
- 与其他正在工作的 Agent 的边界。

优先分派能够独立完成的研究、实现或审查。研究 Subagent 返回来源和结论，不替用户批准；审查 Subagent 默认只报告；多个写入 Agent 不共享所有权。

Subagent 完成后，主 Agent 检查证据、解决冲突、运行集成验证，再更新权威与 `PROJECT_STATE.md`。不要把未经复核的 Subagent 摘要当成项目事实。

## 文档规则

- 只保存会跨任务复用、重新发现成本高或用于审批的内容；
- 保留用户原始素材和表达，但区分原始输入、Agent 推断与批准决定；
- 不用空模板制造虚假完整性，省略当前不适用的章节；
- 优先使用稳定路径和机器可读契约，记录外部来源和查询日期；
- 不把密钥、令牌、私有连接 URL 或环境秘密写入文档；
- 文档与真实实现不一致时明确标记冲突，不仅凭修改时间选择一方。
