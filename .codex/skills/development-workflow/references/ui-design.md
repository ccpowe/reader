# UI 与视觉设计

## 何时读取

在产品存在可见界面，需要探索或修改美术方向、静态布局、视觉素材、响应式构图或页面外观时读取。

## 必须读取

- `PROJECT_BRIEF.md` 中的原始视觉素材与偏好；
- `PRODUCT.md` 中的用户流程、页面职责和重要状态；
- `PROJECT_STATE.md`；
- 已存在的 `DESIGN.md`、页面设计文档、Penpot 设计和真实页面。

## 本阶段负责决定

- 跨页面 UI 风格、色彩、字体、材质、图形和素材语言；
- 主要页面的静态信息层级、布局和响应式意图；
- 哪些生成或现有素材进入产品；
- 哪个 Penpot 方向获得用户批准。

本阶段不决定产品是否需要某项功能，也不以静态设计替代真实动画、交互、数据和运行状态验证。

## 工作方式

### 1. 建立 Penpot 设计上下文

把 Penpot 作为用户可直接查看和批准静态页面的共享设计空间。只有用户打开目标设计并通过 `File > MCP Server` 建立连接后才使用 Penpot MCP；先只读检查当前文件、页面和 Frame，再进行编辑。没有现有设计时，请用户打开一个用于本项目的目标文件。

不要假设 Penpot 与代码同步。记录设计对象、批准状态以及它与真实页面的关系。

### 2. 并行探索视觉方向

根据产品和原始素材定义共同约束，然后并行制作若干真正不同的方向。差异必须体现在构图、视觉语言、密度、字体或素材策略，不只是换颜色。

存在多个可用设计 Subagent 时，把每个方向分配到独立命名的 Penpot Page 或 Frame，并明确对象所有权；不要让多个 Agent 同时修改同一 Frame。没有并行设计 Agent 时，也要从相同输入独立建立各方向，避免让后一个方案只是前一个方案的微调。

图片承担主要视觉表达时，使用 Imagegen 通过相互独立的并行生成探索不同艺术方向；不要把所有变体串在同一连续微调链上。用户选定方向后，再围绕获批风格做连续细化。

头像、图标背景、装饰纹理等普通 UI 素材可以在获批风格约束下自主生成或选择，但仍要记录来源和用途。

在 Penpot 中把不同方向放入清晰命名、互不冲突的 Frame。展示真实产品结构和代表性内容，使用户能比较最终产物的大致样子，而不是只看色板或文字描述。

### 3. 与用户收敛

先让用户比较方向，再围绕选中方向修改。记录用户喜欢、排斥和要求保留的具体部分，不把“都不错”误写成批准。

静态布局、视觉风格或主要素材改变时继续在 Penpot 中确认。动画曲线、手势、过渡时间和运行时反馈只记录为实现输入，在代码阶段验证。

### 4. 固化设计契约

批准后更新：

- Penpot 中获批的文件、页面和 Frame；
- `DESIGN.md` 中跨页面复用的设计语言、精确令牌和规则；
- 必要的页面级设计文档，其中记录对应 Frame、静态结构、响应式意图、重要状态与待实现交互；
- 素材清单及来源、许可和用途。

`DESIGN.md` 不保存技术栈，也不复制每个页面的完整结构。页面级决定留在页面文档和 Penpot。

## 用户确认点

- 并行探索中选定的总体艺术方向；
- 主要页面的静态布局和信息层级；
- 会定义品牌身份的核心素材；
- 对既有获批方向的实质改变。

## 持久产物与退出门槛

产出获批 Penpot 设计、`DESIGN.md`、必要页面设计文档和素材清单，并在 `PROJECT_STATE.md` 中记录对象与状态。

当用户能够直观看到主要页面的大致最终效果、全局设计规则可复用、未解决的动画与交互已经明确交给实现阶段时停止。

## 影响检查

- UI 暴露缺失功能、页面或状态：返回产品阶段；
- UI 需要新数据或能力：通知架构阶段；
- 静态契约变化：把对应前端实现标记为 `needs-review`；
- 实现中的交互要求改变布局：返回 Penpot 重新批准受影响部分。
