> 数据来源：`references/capture/`（extract.json 19 次扫描 / 340 条动画 / 32 条 hover，components.json 33 个组件，focus.json 64 次 Tab 焦点）+ 截图 V1–V8、D-*。
> 标注：`[测量]` = capture 中 getComputedStyle / 动画记录的真实值；`[估计]` = 看截图推测；`无法判断` = 数据和截图都不足以下结论。

## 1. 信息架构

### 观察
- **三栏结构，只有两栏常驻**：左侧侧边栏宽 270px `[测量]`（`nav.notion-sidebar-container 270x900`），右侧主区 `main.notion-frame` 宽 1170、高 856，上方是 44px 高的顶栏 `[测量]`。第三栏（Side Peek）只在打开记录时出现：宽 960px，从视口右边贴边弹出，把主区压到 480px `[测量]`（V8）。
- **侧边栏从上到下（V1、D-sidebar）**：
  1. 工具行：折叠侧边栏、收件箱、新建页面，图标按钮 28×28 `[测量]`。
  2. 搜索框 “Search or ask”，右侧有 `Ctrl+K` 键帽提示，246×32 `[测量]`。
  3. Home / 聊天 / 日历三个 tab，32px 高 `[测量]`。
  4. 固定入口：New page / New chat / Library。
  5. 分组：Upcoming events / Shared / Private，组标题 12px/500 `[测量]`。
  6. 页面树（treeitem 30px 高，项与项之间 1px 间隙）`[测量]`。
  7. 底部：工作区切换器 “zz chai's Notion”、帮助、应用切换。
- **常驻 vs 隐藏**：
  - 常驻：页面树、搜索入口、当前页标题与面包屑（顶栏左侧 “Design Capture Demo · Private”）、Share、收藏、更多（顶栏右侧）。
  - hover 才出现：树节点的展开箭头（hover 时页面图标被箭头替换）、`+` 和 `···`（D-sidebar 中 “Design Capture Demo” 一行）`[测量：hover 记录里 20×20 按钮 opacity 0→1]`；表格行左侧的拖拽手柄和勾选框（opacity 0→0.7 / 0→1）`[测量]`；行内 “OPEN” 按钮（V8 中的 CLOSE/OPEN 胶囊）。
  - 打字时淡出：顶栏 `notion-topbar` 在键盘输入或方向键操作时 opacity 1→0（700ms），鼠标移动后恢复 `[测量：I4-arrow、I2-open-search、C-settings-navigation 中都有记录]`。
  - 召唤才出现：Ctrl+K 搜索、`/` 斜杠菜单、··· 上下文菜单、设置弹窗。
- **导航模型**：
  - 树形层级（treeitem）+ 面包屑。
  - 全局跳转靠 Ctrl+K 搜索面板（左边结果列表 + 右边预览卡）。
  - 记录详情有三档：Side Peek（侧边打开）→ 新标签打开（`Ctrl+⇧+↵`）→ 全页（V8 左上 `»` 和 `↗`）。
  - 设置是全屏遮罩上的大弹窗（1296×800），弹窗内部再分左侧导航（240px）和右侧内容 `[测量]`。
- **主要任务**：阅读和编辑正文（文档页）、用表格管理结构化记录（数据库）、找到某个页面（搜索 / 树）。设置属于低频任务，放在弹窗里。

### 解释
- 正文是唯一的主角，其他导航都能收起或淡出（顶栏打字时淡出、hover 才出现的操作），这样写作时视野里只剩文字。
- “召唤式” 入口（`/`、Ctrl+K、···）把功能数量和界面复杂度分开：功能再多，静止状态下屏幕上的控件也不会变多。
- Side Peek 让人不离开列表就能看详情，保留了 “我在表格的哪一行” 这个上下文。

### 可复用规则
- R1.1 两栏常驻（导航 + 内容），第三栏（详情 / 评论）按需滑出，宽度为视口的 2/3 左右（960/1440）。
- R1.2 次要操作挂在对象上，hover 或聚焦时才出现；静止状态下每一行只显示内容本身。
- R1.3 低频的全局功能（设置）用大弹窗；高频的全局功能（搜索、插入块）用快捷键唤出浮层，并且在入口处显示快捷键（`Ctrl+K`、`esc`、`#`）。
- R1.4 用户开始键盘输入时，淡出与输入无关的 chrome（顶栏），鼠标移动后再恢复。

## 2. 视觉层级

### 观察
- **第一眼**：文档页的页面标题 40px/700 `[测量]`，是全屏唯一的大字号、粗字重元素；它所在的列宽 708px，在 1170 的主区里居中（左边距约 223px）`[测量 + 推算]`。
- **第二眼**：正文 16px/24px/400，颜色 #2c2c2b `[测量]`。H1/H2/H3 分别是 30/600、24/600、20/600 `[测量]`，靠字号差拉开层级，字重都是 600。
- **侧边栏退后**：
  - 背景 #f9f8f7，比主区白色略暗 `[测量]`。
  - 条目文字 14px/400，颜色 #5f5e59，对比度 6.5:1 `[测量 + 计算]`，比正文 #2c2c2b（14:1）明显浅。
  - 选中项文字变为 #2c2c2b，并加 rgba(33,27,23,0.05) 的底色 `[测量]`。
  - 组标题 12px/500，颜色 #a19e99 `[测量]`。
- **几乎不用强调色**：全屏只有主按钮（New / Add members）、开关打开态、链接、焦点环和 “Upgrade plan” 用蓝色 #2783de `[测量]`。V1 文档页在去掉插件之后，没有任何蓝色。
- **分组靠留白和细线，不靠卡片**：
  - 设置页的分区是 “16px/500 标题 + 1px 分隔线 + 段落”（V4），没有卡片背景。
  - 表格只用 1px 线 rgba(42,28,0,0.07)（共 981 次，是出现最多的边框色）`[测量]`。
- **唯一用填充色分组的例子**：callout，背景 rgba(66,35,3,0.03)，圆角 10px `[测量]`。

### 解释
- 层级主要靠 “字号 + 位置 + 明度” 三个手段，颜色和阴影几乎不参与。这样页面里的彩色内容（用户的 emoji、标签、封面）不会和界面 chrome 抢注意力。
- 侧边栏整体降一档明度、文字降一档颜色，正文就天然成为视觉中心。这正是 notes 里说的 “侧边栏很安静”。

### 可复用规则
- R2.1 每屏只有 1 个最大字号元素（页面标题）；标题层级只靠字号区分，字重统一。
- R2.2 导航区比内容区背景暗一级（#fff → #f9f8f7），文字也降一级颜色；选中项通过 “文字恢复为主色 + 5% 底色” 来强调。
- R2.3 强调色只用于：主操作按钮、开关打开态、链接、焦点环。导航选中态**不用**强调色。
- R2.4 分组的优先级：留白 > 1px 分隔线 > 3% 底色块（callout）> 卡片。阴影只留给浮层。

### 3.6 边框与阴影
- 计算出的边框宽度全部是 **0.666667px** `[测量]`。在 DPR≈1 下应该渲染成 1 个物理像素的细线，为什么写成这个值：无法判断。
- **很多描边用 box-shadow 而不是 border**：
  - 侧边栏右缘：`inset -1px 0 0 #f0efed`。
  - 浮层统一带 `0 0 0 1px rgba(42,28,0,0.07)` 外环 `[测量]`。

### 3.7 图标
- 尺寸：20×20 ×324、16×16 ×207、18×18 ×167、14×14 ×94、22×22 ×92 `[测量]`。

- 图标是单色线性 SVG，用 `graphics-symbol` role，按 class 名看（ellipsisSmall、arrowChevronSingleDown…）是自有图标集。描边约 1.25–1.5px `[估计，看 D-menu-container]`。
- 颜色：只有两档灰，#8e8b86（icoSec，×35 作为文字色）和 #55534e（作为 mask 背景色）`[测量]`。没有任何彩色 UI 图标，彩色只来自用户 emoji。
- 图标和文字之间 8px（margin-right 8px，×267）`[测量]`。图标容器 22×22 或 20×20，居中对齐文字行。

### 3.8 信息密度
- 表格行 37px（36.67），一屏（856 高的主区）大约显示 18 行 `[测量 + 计算]`。
- 侧边栏行距 31px（30 + 1）`[测量]`。
- 菜单项 28px，斜杠菜单项 32px `[测量]`。
- 正文行高 1.5（16/24），块与块之间 2px padding + 约 4–8px 间距 `[估计]`。
- 结论：界面 chrome 是**中高密度**（28–32px 行），阅读区是**舒适密度**（16/24、708px 宽，约 75–85 个英文字符一行）。

### 解释
- 系统字体 + 一个中性暖灰体系，品牌感几乎全部来自 “克制”：没有品牌字体，也没有品牌色铺底。
- 半透明的 hover / 边框色（rgba 暖黑）放在任何浅底上都能自动适配：同一个 0.05 hover 在白底和 #f9f8f7 底上都成立。
- 浮层用 “极淡的大扩散阴影 + 1px 环” 而不是深阴影，所以浮起来但不显得重。

### 可复用规则
- R3.1 字号只用 11 / 12 / 13 / 14 / 16 / 20 / 24 / 30 / 40；字重只用 400 / 500 / 600 / 700，700 只给页面标题。
- R3.2 chrome 的默认文字是 14px，内容的默认文字是 16px，二者不混用。
- R3.3 间距只用 1 / 2 / 4 / 6 / 8 / 12 / 16 / 24 / 32 / 48。
- R3.4 圆角随容器尺寸递增：控件 6、菜单 10、弹窗 12、全屏面板 20、胶囊 999。
- R3.5 hover / pressed / border 都用**半透明暖黑**（rgba(33,27,23,α)），不用实色灰。
- R3.6 阴影只用于浮层，并且总带一圈 1px 半透明环。
- R3.7 单元格里的数字使用 tabular-nums。

## 4. 交互模型

### 观察
- **hover**：
  - 所有行和按钮的 hover 都是透明 → rgba(33,27,23,0.05) 底色，文字不变 `[测量]`。
  - 例外：侧边栏底部 28×28 的图标按钮 hover 时文字/图标从 #7d7a75 变成 #2c2c2b `[测量]`。
  - hover 不使用位移、缩放或阴影 `[测量：hover 记录中 transform 均为 none，排除右下角按钮]`。
- **pressed**：底色升到约 0.10（动画中出现 α=0.102 的中间目标）`[测量]`。
- **选中态（selected）**：0.05 底色，hover 时升到 0.076 `[测量 settings tab]`。斜杠菜单 / 搜索的 “键盘当前项” 也是 0.05 底色 `[测量]`，所以 hover 和键盘选中**共用同一视觉**。
- **主按钮 hover**：#2783de → #1f76cc，加深一级，20ms `[测量]`。
- **次按钮（蓝色 soft）hover**：α 0.094 → 0.141，100ms `[测量]`。
- **焦点**：
  - Tab 聚焦（focus-visible）时出现三层 box-shadow 环：2px #f8f8f7 内隔 + 2px #2383e2 + 2px rgba(255,255,255,0.25)，环宽合计 6px `[测量 focus.json 33+5+4 次]`。
  - outline 设为 transparent。焦点环有 100ms ease-in 过渡 `[测量]`。
  - 文本输入框的焦点是 `inset 0 0 0 1px #2383e2, 0 0 0 1px #2383e2`，即 2px 蓝边 `[测量 customProperty --c-inpBluFocRin，截图 V-settings-preferences 搜索框可见]`。
  - 开关 input 本身 opacity 0，焦点记录为 none。视觉轨道上有没有焦点环：**无法判断**。
- **键盘**：
  - Ctrl+K 打开搜索；↑↓ 移动选中项（I2-arrow、I4-arrow 中背景色切换 20ms）`[测量]`。
  - esc 关闭斜杠菜单（菜单底部 “Close menu · esc”）。
  - 菜单项右侧显示快捷键：`Ctrl+D`、`Ctrl+⇧+R`、`#`、`##`。
  - `/` 唤出插入菜单，并在原位置显示 “Type to search” 占位 `[截图 V6]`。
- **反馈**：
  - 加载用 1200ms 线性旋转的 12px spinner，以及 1000ms 线性 shimmer 骨架条 `[测量 I2-type、C-settings-navigation]`。
  - Toast：未采集到，**无法判断**。
- **可撤销 / 可中断**：
  - 所有浮层和 hover 过渡都是 CSS transition。中途反向时，会从当前值以缩短的时长返回（tooltip 退出 9.9ms、菜单 160ms / 119ms）`[测量]`，所以是**可打断、可反向**的。
  - “Move to Trash” 不弹确认框（菜单项直接执行）`[估计 V7，没有采集删除后的流程]`。是否有撤销 toast：**无法判断**。
- **空状态**：
  - 空数据库单元格什么都不显示。
  - Side Peek 中空属性显示灰色 “Empty”（V8 Parent item）。
  - 空页面底部提示 “Press 'enter' to continue with an empty page, or create a template”（V8）`[截图]`。

### 解释
- hover 只改底色，是 “轻反馈” 的核心：不移动布局，也不吸引额外注意力（notes：“悬停反馈很轻，不突兀”）。
- 键盘选中和鼠标 hover 用同一视觉，避免出现 “两个高亮” 的歧义。
- 焦点环只在 focus-visible 时出现，鼠标用户看不到它，键盘用户得到很明显的 4px 蓝环。

### 可复用规则
- R4.1 交互态只改背景透明度这一个维度：rest 0 → hover 0.05 → pressed 0.10；selected 0.05，selected+hover 0.076。
- R4.2 hover 不改布局、不缩放、不加阴影。
- R4.3 键盘当前项 = hover 视觉；同一列表里同时只能有一个高亮项。
- R4.4 焦点环只用 focus-visible：2px 底色间隙 + 2px 强调色环；文本输入框用 1px 内 + 1px 外的强调色描边。
- R4.5 所有状态过渡都用 CSS transition，保证能被中断和反向。

## 8. Anti-patterns（来自 notes.md 的 “不喜欢”）

### AP1 文字太灰，看不清
- **现象 `[测量 + 计算]`**：
  - #a19e99 在白底上 2.67:1、在 #f9f8f7 上 2.52:1，却承担了 4 种需要阅读的角色：占位符、分组标题、元信息（“zz chai · Edited Just now”）、快捷键提示。
  - #7d7a75 在 13px 说明文字上是 4.27:1。
- **禁止**：任何**承载信息**的文字低于 4.5:1。低于 4.5:1 的颜色只能用于 disabled 状态，以及纯装饰元素（分隔符 “·”）。
- **改法**：沿用 Notion 自己的灰阶，但整体上移一档。
  - 次要文字：#7d7a75 → #5f5e59（6.5:1）。
  - 三级文字 / 占位符 / 分组标题：#a19e99 → #73726e（4.82:1）。
  - 这样仍保留 “三档灰” 的结构和整体淡调，只是最浅的一档不再不可读。

### AP2 图标太淡、太单调
- **现象 `[测量]`**：所有 UI 图标只用 #8e8b86（3.39:1）/ #55534e 两档灰；页面类型（文档 / 数据库 / 聊天 / 日历）只靠线稿形状区分，和同色文字混在一起，强弱分不出来。
- **禁止**：
  1. 所有图标统一一种灰色。
  2. 图标颜色和相邻文字完全相同、却又承担类别区分的功能。
- **改法**：
  - **对象类图标**（页面类型、文件类型、分组类别）按类别上色，使用中饱和的 “500” 级色。这些颜色在 #fff 和 #f9f8f7 上都 ≥ 3:1（非文本对比度标准）。
  - **操作类图标**（关闭、更多、chevron、+）保持中性灰，但改用 #73726e（≥ 4.5:1）。
  - 背景、文字和大面积区域依然保持中性淡色，颜色只出现在 ≤ 20px 的图标上。

### AP3（推论）主按钮文字对比不足
- **现象**：#f3f9fd on #2783de 为 3.67:1 `[计算]`。notes 没有直接提到这一点，但它和 AP1 是同一类可读性问题，所以一并记下。
- **改法**：主按钮背景改用 Notion 的 hover 色 #1f76cc（4.64:1），hover 再加深到 #105fad。#2783de 保留给焦点环、开关等非文字场景。这一项需要人确认，见 DESIGN.md “已知不足”。

## 9. 无法判断清单

- Side Peek、侧边栏折叠、搜索面板的实际运动（CSS 没有记录到运行；没有录屏）。
