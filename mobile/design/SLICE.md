# SLICE.md — 第 4 步：布局探索

> 依据：`PRODUCT.md`（P1–P20）。本轮**只探索布局**，不套风格包（流程第 4 步）：一律用中性灰阶、系统字体、
> 统一的 8px 间距和 1px 边框；颜色、字号、圆角、图标风格留到第 5 步套 quietpaper 时再定。
> 总原则 P12：每个区域的方案 A 都是**现状**，其他方案必须能说出"它解决了现状的什么问题"。

## 形式
- 做成 React Native Storybook 的 story（P10），在 Expo Go 里看（用户手机已装 Expo Go）。
- 每个区域一个分组，每个方案一个 story，名字形如 `R1-A 现状`、`R1-B 紧凑`；另有一个"对比" story 把各方案上下排在一起。
- 屏幕宽度按 360～412dp 的 Android 手机设计；每个 story 都放**真实长度的示例数据**（见每节"数据"）。
- 只做显示和点击反馈，不接后端；点按钮只需要有按下效果，必要时用一句提示说明会发生什么。

## R1 今天页的信息卡片（含 X 卡片）
**为什么要看**：出现次数最多，最影响观感；新增"共 N 条"串标记（P17），书签按钮位置（P19）要在每个方案里都放好。

| 方案 | 结构 | 解决现状的什么问题 |
|---|---|---|
| **A 现状** | 来源头像 + 名字 + 时间；标题（最多 3 行）+ 右侧方形缩略图；摘要 2 行；书签在右上 | — |
| **B 紧凑** | 来源 + 时间一行小字；标题最多 2 行 + 右侧小缩略图；不显示摘要；书签在右侧居中 | 订阅很多时，一屏能看到更多条（约 1.5 倍） |
| **C 标题优先** | 标题在最上面（最多 3 行），来源 + 时间放在标题下方一行；摘要 2 行；缩略图在右；书签跟在来源行末尾 | 让"这条是什么"先被看到，来源退到次要位置 |

X 卡片在三个方案里都沿用现状的层级（P16）：作者行、正文预览（最多 6 行）、引用 / 转发用带边框的内嵌卡片、
回复显示"回复 @某人"；**"共 N 条"**在 A/C 里放在正文下方左侧，在 B 里放在来源行末尾。

**数据**：普通文章 ×3（标题 18 字 / 60 字 / 140 字；有图 / 无图；摘要 0 / 80 / 280 字）、X 帖子 ×3
（短帖、带引用、自回复串 7 条）、来源名 2～40 字、已收藏 / 未收藏各有。

## R2 榜单页的顶部
**为什么要看**：Product Hunt 改成"今天 / 昨天"两个按钮、Reddit 可输入任意社区、新增数据新旧与暂停提示（P17）。

| 方案 | 结构 | 解决现状的什么问题 |
|---|---|---|
| **A 现状** | 顶部一排榜单标签（左右滑动切换）；右上角"调整"按钮打开选项弹层（周期 / 日期 / 社区 / 排序）；数据新旧以一行小字放在列表最上方 | — |
| **B 版本直接摆出来** | 榜单标签下面第二行是当前榜单的版本按钮（GitHub 日周月、PH 今天/昨天、Reddit 排序）；Reddit 社区用一个可点的"r/python ▾"打开弹层；新旧提示在第二行右端 | 切换版本少点一次；当前看的是哪个版本一眼可见 |
| **C 标题即选择器** | 页头标题就是当前榜单名，点开弹层选榜单和版本；列表顶部一行显示"版本 · x 分钟前" | 顶部更干净，留更多高度给列表 |

**暂停 / 过期提示**在每个方案里都要放：数据新鲜、"x 分钟前（已过期）"、"暂停中：被限流，约 8 分钟后恢复"、
"暂不可用：需要浏览器验证"（TechTwitter）四种。

**数据**：五个榜单各 5 条（HN、GitHub 周榜、PH 今天、Reddit r/python 热门、TechTwitter 新闻格式）；Reddit 社区名 2～21 字。

## R3 阅读页的工具条
**为什么要看**：阅读时一直在屏幕上；三种翻译显示（原文 / 双语 / 只看译文，P15）现状只能在原文和双语之间切换，
"只看译文"不好找；收藏、打开原链接在顶部标题栏。

| 方案 | 结构 | 解决现状的什么问题 |
|---|---|---|
| **A 现状** | 右侧一组可上下拖动的悬浮按钮：翻译开关 + 切换视图（原网页 / 阅读模式；播放器 / 网页）；收藏、打开原链接在顶部标题栏 | — |
| **B 悬浮按钮 + 长按菜单** | 同 A，但长按翻译按钮弹出"原文 / 双语 / 只看译文"三选一 | 三种翻译都能到，单击仍是最常用的切换 |
| **C 底部工具栏** | 屏幕底部一条固定工具栏：返回、翻译（三段切换）、视图切换、收藏、分享；向下滚动时收起，向上滚动时出现 | 所有操作集中在拇指能够到的地方；不遮挡正文 |

**数据**：网页文章（阅读模式与原网页两种状态，用静态占位页面代替 WebView）、YouTube（播放器占位 + 字幕时间轴 8 行）；
翻译进行中（按钮转圈）、额度用完（提示"约 1 分钟后可再试"）两种状态。

## R4 订阅列表行的健康提示
**为什么要看**：新增（P17）。扫描失败、可能有遗漏时要能被发现，又不能让列表显得到处是警告。

| 方案 | 结构 | 解决什么问题 |
|---|---|---|
| **A 只加小圆点** | 现状的订阅行（头像、名字、类型、新内容数），出问题时名字右边一个小圆点；点行内的圆点打开说明弹层 | 最安静 |
| **B 行内一行说明** | 出问题的行在名字下面多一行小字："扫描失败 · 网站连不上 · 3 小时前" | 不用点就知道原因 |
| **C 顶部汇总 + 行内图标** | 列表顶部一条"2 个订阅有问题"，点开只显示有问题的订阅；行内一个小图标 | 问题集中处理，平时列表保持干净 |

（现状没有健康提示，所以这里的 A 是"在现状行上加得最少"的方案。）

**数据**：12 个订阅分 3 个文件夹，其中正常 9、扫描失败 2（网站连不上 / X 服务没配置）、可能有遗漏 1；名字 2～40 字。

## 不在本轮
- 其余区域（标签栏、页头、我的、收藏、登录）沿用现状布局，第 5 步套风格时一起出现。
- 深色模式、手机组件的风格补充：第 5、6 步。

## 给用户看的方式
只看这 4 个区域，**按区域选**（可以 A 的卡片 + C 的工具条），每个区域标出最喜欢的一个，有想法写一句。
